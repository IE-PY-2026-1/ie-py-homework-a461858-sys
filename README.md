## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문
### **✨2차 과제 내용:**
  * 이번 과제는 콘솔 기반 투두리스트 관리 시스템 구현으로, 사용자로부터 할 일과 관련 정보를 입력받아 리스트에 저장하고 이를 효율적으로 관리하는 프로그램을 구축하는 것입니다. 특히 if-elif 조건문을 활용하여 중요도에 따라 할 일을 볼 수 있고, 추후 오늘의 기분을 입력하면 하루의 행운의 색이 나오는 요소를 리스트와 조건문, input()을 활용해 구현할 예정이다.
  * input()을 통해 할 일 내용과 중요도(높음/보통/낮음)를 입력받아 리스트에 저장.
  * 리스트(list)를 활용하여 여러 개의 할 일을 관리하고, 카테고리(공부 / 할일 / 기분)에 따라 데이터를 구분하여 저장.
  * if-elif-else를 사용하여 중요도에 따라 다른 메시지를 출력하는 조건문 로직 구현.
  * 추가적으로 리스트에 저장된 데이터를 활용하여 ‘오늘의 행운의 색’과 간단한 조언을 출력하는 기능을 구현할 예정으로, 프로그램에 재미 요소를 더하고 사용자 참여도를 높이는 방향으로 확장함.
    
### **🤖 AI 파트너십 과정**
  
1. **내용 1: 리스트와 조건문을 결합한 확장 로드맵 자문**
   * **프롬프트 요약:** "파이썬 기초 문법 단계(리스트 → 조건문 → 반복문 → 함수)에 맞춰, '행운의 투두리스트'가 어떻게 발전할 수 있을지 4단계 확장 로드맵을 제안해줘."
   * **적용 내용:** 단순한 텍스트 출력을 넘어, '기초 정보 입력 및 변수 저장, 리스트와 조건문을 활용한 할 일 분류 및 중요도 판별(2차) → 반복문을 이용한 메뉴 시스템과 기분 기반 행운의 색 매칭(3차) → 딕셔너리와 함수를 활용한 구조화된 데이터 관리(4차)'로 이어지는 논리적인 확장 로드맵을 확립함.

2. **내용 2: 효율적인 데이터 분류 및 필터링 로직 도출**
   * **프롬프트 요약:** "2차 과제 수준에서 리스트와 조건문만 사용해 할 일을 효과적으로 관리할 방법이 있을까? 중요도에 따라 다른 메시지를 보여주고 싶어."
   * **적용 내용:** 입력받은 중요도 점수를 int()로 형변환하여 수치화하고, if-elif-else를 통해 점수가 높은 항목에는 "🔥 긴급"과 같은 상태 메시지를 부여하는 필터링 로직을 설계함. 또한 카테고리(공부, 운동 등)에 따라 맞춤형 한줄평을 출력하는 기능을 추가하여 조건문의 활용도를 높임.
    
### **🛠️ Troubleshooting & 기술 회고:**
1. **문제 1: 중첩 리스트의 특정 데이터에 접근할 때 발생하는 혼란 (IndexError/Logical Error)**
   * **원인:** 할 일을 [task, category, priority] 형태로 리스트 안에 리스트로 저장했는데, 중요도만 꺼내서 비교하고 싶을 때 인덱스 번호를 어떻게 써야 할지(todo_list[0][2] 등) 헷갈려 데이터가 잘못 출력되거나 오류가 발생함.
   * **해결:** 리스트의 구조를 시각화하여 첫 번째 대괄호는 '몇 번째 할 일'인지, 두 번째 대괄호는 '그 안의 구체적인 정보'인지를 파악함. 인덱스는 0부터 시작한다는 원칙을 다시 복습하여 정확한 위치의 데이터를 참조하도록 수정함.
2. **문제 2: 상세 조회(서브 메뉴) 시 입력값의 타입 불일치**
   * **원인:** 첫 번째 메뉴 선택(choice)은 문자열('2')로 처리하고, 이후 중요도를 선택하는 창에서 받는 값은 숫자(int)로 처리하는 과정에서 타입을 혼동하여 조건문이 항상 거짓이 되는 문제가 발생함.
   * **해결:** 비교 대상이 리스트 내부의 숫자 데이터라면 입력값도 반드시 int()로 형변환해야 한다는 점을 명확히 인지하고, 서브 메뉴의 입력값도 형변환을 적용하여 타입을 일치시켜 해결함.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문)
### **✨3차 과제 업데이트 내용:**
* 기존의 단발성 실행 구조를 `while True` 무한 루프를 활용한 지속적인 '메인 메뉴 시스템'으로 전환함.
* 프로그램의 가독성과 유지보수성을 극대화하기 위해 기존 코드를 기능별로 최소 3개 이상의 개별 함수(`def`)로 분리 및 구조화.
* 특히 사용자가 입력한 오늘의 기분 점수와 할 일 데이터들을 연산 처리하기 위해, 함수 간 매개변수(인자) 전달 및 `return` 문을 통한 결과값 반환 로직을 유기적으로 연결.
* 전역 변수(`global`)를 활용하여 프로그램이 종료되기 전까지 등록된 데이터가 누적되고 유지되도록 구현함.
    
### **🤖 AI 파트너십 과정**
 1. **내용 1**
    * **프롬프트 요약:** "기존에 작성한 if-elif-else 중심의 투두리스트 코드를 def를 사용해 나만의 함수로 깔끔하게 정리하고 싶어. 어떤 카테고리(기능)로 함수를 나누는 것이 좋을까?"
    * **적용 내용:** 코드의 역할에 따라 input_todo() (입력), show_all_tasks() (전체 조회), show_tasks_by_priority() (중요도 필터링), show_tasks_by_category() (카테고리 필터링)의 4가지 독립된 함수로 구조화함. 이 과정에서 기존 코드의 인덴트(들여쓰기) 오류로 인해 데이터가 1개만 저장되거나 0번 인덱스만 조회되던 버그를 수정하고, 반복문을 통해 전체 데이터를 유동적으로 탐색하도록 개선함.

 2. **내용 2**
    * **프롬프트 요약:** "함수 개념을 활용해 현재 남은 할 일 개수로 운세 점수를 계산하고, 사용자의 기분 상태까지 조합하여 행운의 색과 모험가 칭호를 유동적으로 분석해 주는 파이썬 코드를 짜줘."
    *  **적용 내용:** calculate_fortune_score(task_count) 함수에서 남은 할 일 개수에 따른 감점 방식(max(0, final_score))으로 활력 지수를 수학적으로 연산하고 이를 반환(return)하도록 설계함. show_fortune() 함수 내에서 len(tasks)로 구한 데이터 개수를 타 함수로 전달(호출)하여 연동성을 높였으며, and 논리 연산자와 if-elif-else 다중 조건문을 결합하여 점수와 기분 상태에 따라 S~F등급의 특별 칭호 및 행운의 색을 부여하는 종합 분석 시스템을 확립함.
    
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 무한 루프 구현 시 발생한 구문 오류 (SyntaxError: while ture:)
     * **원인:** 잘못된 입력을 걸러내기 위해 올바른 값을 넣을 때까지 무한 반복하는 예외 처리 로직을 구현하려 했으나, 파이썬의 예약어인 True의 첫 글자를 소문자로 쓰거나 오타를 내어 while ture:라고 작성함. 파이썬이 ture를 정의되지 않은 변수로 인식해 문법 오류가 발생함.
     * **해결:** 파이썬의 불리언(Boolean) 가리킴 값은 대소문자를 엄격히 구분하여 반드시 첫 글자를 대문자인 True로 작성해야 함을 인지함. 코드를 while True:로 정확히 수정하여 에러를 해결하고 유효성 검사 루프를 정상 작동시킴.
    
  2. **문제 2:** 단수형 변수(task)와 복수형 리스트(tasks)의 이름 혼동 (NameError/Logical Error)
     * **원인:** 전체 할 일 목록을 담고 있는 전체 리스트(tasks)와, 반복문 내부에서 새로 입력받거나 하나씩 꺼내 쓰는 단일 항목 변수(task)의 이름이 형태가 비슷하다 보니 코딩 과정에서 서로 뒤바꿔 사용함. 이로 인해 리스트 전체에 문자열이 통째로 덮어씌워지거나, 단일 변수에 .append()를 시도하다가 프로그램이 멈추는 논리적 오류가 발생함.
     *  **해결:** 데이터의 성격에 따라 데이터 '묶음(리스트)'은 복수형 명사(tasks), 개별 '원소'는 단수형 명사(task 또는 t_input)로 명확하게 변수명을 분리하고 네이밍 규칙을 세움. 코드를 전면 재검토하여 데이터가 들어갈 올바른 방을 찾아 매핑해 줌으로써 데이터 유실 문제를 해결함.

### 🟥 [4차 과제: V4.0] 모듈화 및 데이터 확장 (배열과 함수) - 🌟최종 완성 - 다차원 데이터 관리 및 예외 처리 시스템 구축
### **✨4차 과제 업데이트 내용:**
  * 다차원 데이터 구조화 (이중 리스트 활용): 기존의 단일 데이터 저장 방식을 넘어, 여러 명의 데이터를 동시에 체계적으로 관리할 수 있도록 [작성자 이름, 날짜, 할 일, 카테고리, 중요도] 구조의 이중 리스트 형식을 새롭게 도입함.
  * 조건별 다차원 순회 출력 구현: 중첩 구조 및 인덱싱 활용 능력을 극대화하여 전체 목록 조회뿐만 아니라 중요도별, 카테고리별, 특정 날짜별로 이중 리스트의 데이터를 사용자가 원하는 특정 포맷에 맞춰 깔끔하게 반복 출력하도록 고도화함.
  * 파일 영구 저장 시스템 (File Write) 도입: with open() 함수를 사용하여 프로그램이 종료되기 전이나 특정 메뉴를 선택했을 때, 메모리에만 임시로 존재하던 이중 리스트 데이터를 todolist.txt 텍스트 파일에 행(Line)별로 안전하게 기록하는 파일 입출력 기능을 구축함.
    
### **🤖 AI 파트너십 과정**
 1. **내용 1**
    * **프롬프트 요약:** "기존 투두리스트에 '작성자 이름'과 '날짜' 데이터를 추가해서 이중 리스트 형태로 확장하고 싶어. 여러 명의 데이터가 섞여도 날짜별, 카테고리별로 완벽하게 골라내어 표 형태로 출력할 수 있는 다차원 리스트 구조와 검색 로직을 제안해줘."
    * **적용 내용:** AI가 자문한 [user_name, task_date, t_input, c_input, p_input] 구조의 5열 이중 리스트 설계 방식을 채택했습니다. 데이터가 누적될 때 각 원소의 고유한 방 번호(인덱스 0~4번)가 엇갈리지 않도록 방지하고, 중첩 순회(for row in todo_list:) 과정에서 원하는 조건의 인덱스 값을 정확히 비교 추출하여 화면에 바인딩하는 복합 필터링 로직을 코드에 성공적으로 반영함.

2. **내용 2**
   * **프롬프트 요약:** "이중 리스트로 확장된 투두리스트 데이터를 프로그램 종료 시 텍스트 파일에 행별로 누적 저장하고 싶어. 더불어 중요도를 입력받을 때 문자를 넣거나 파일 시스템에 문제가 생겨도 프로그램이 강제로 꺼지지 않도록 try-except를 배치하는 효율적인 위치를 알려줘."
   * **적용 내용:** AI의 조언에 따라 정수 변환 시 ValueError가 발생할 수 있는 입력부와, 입출력 에러 위험이 있는 파일 쓰기 공정에 try-except 블록을 분리 배치하여 다중 예외 처리 구조를 확립했습니다. 또한 파일 저장 시 데이터가 한 줄로 병합되는 현상을 막기 위해 각 행의 끝에 개행 문자(\n)를 더해 구분 기호(,)와 함께 텍스트 파일에 세로로 정렬되도록 입출력 포맷을 완성함.
    
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 이름 데이터 추가 이후, 항목 조회 및 검색 시 데이터가 엇갈리거나 누락되는 현상
     * **원인:** add_task() 함수에서 리스트의 맨 앞에 user_name을 새로 삽입하면서 리스트 내부 인덱스가 한 칸씩 뒤로 밀렸으나([0]이름, [1]날짜, [2]할일...), 기존 조회 함수인 view_task() 내의 조건문에서는 예전 버전의 방 번호(예: row[0]을 날짜로 비교, row[3]을 중요도로 비교)를 그대로 유지하고 있었습니다. 이로 인해 엉뚱한 카테고리 문자와 숫자를 비교하게 되어 "일치하는 할 일이 없다"는 메시지만 출력되는 논리적 버그가 발생함.
     * **해결:** 데이터 저장 순서에 맞게 인덱스 매핑 규칙을 전면 재정비했습니다. 전체 출력 및 조건 비교 시 이름은 row[0], 날짜는 row[1], 할 일은 row[2], 카테고리는 row[3], 중요도는 row[4]로 명확하게 타겟을 수정해 줌으로써 데이터 구조의 일관성을 회복하고 날짜별/중요도별 검색 기능을 완벽히 복구함.
